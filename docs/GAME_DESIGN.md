# 게임 기획

## 확정된 방향

- Unity와 C#으로 만드는 3D PvE 자동 전투 게임.
- 아군은 인간 군대이며 병종은 일반병, 창병, 기마병이다.
- 적은 고블린 같은 이종족 몬스터다.
- 플레이어가 전투 전에 병력을 배치하고, 전투 시작 후 병사들이 자동으로 이동하고 공격한다.
- 군대 편성과 진형을 짜는 느낌, 병사들이 실제 전장에서 백병전을 벌이는 느낌을 중시한다.
- 병종마다 역할과 전투 방식에 차이를 둔다. 구체적인 능력과 상성은 아직 결정하지 않았다.
- 초기에는 임시 3D 도형을 사용해 전투를 확인한다.

## 미정 사항

| 항목 | 결정 시점 및 원칙 |
| --- | --- |
| 병력 모집, 성장·강화 | 7단계에서 선택지를 비교하고 사용자와 결정 |
| 웨이브, 보상, 전투 후 회복·병력 유지 | 7단계에서 사용자와 결정. 이전 단계의 단일 전투 테스트가 장기 진행 규칙을 확정하지 않음 |
| 병종별 체력·공격력·이동 속도·가격 | 필요한 단계에서 변경 가능한 임시값 사용. 최종 밸런스 미정 |
| 창병·기마병의 구체적 역할과 전투 규칙 | 6단계에서 중요한 선택을 사용자와 결정 |
| 최종 병력 규모, 출시 플랫폼 | 관련 설계가 필요해지는 단계에서 결정 |
| 배치 조작의 구체적인 방식 | 5단계에서 검토. HTML의 격자와 배치 제한은 자동 채택하지 않음 |

## HTML 참고 범위

[기존 프로토타입](../References/prototype.html)은 단일 HTML/CSS/JavaScript 파일로, Canvas 기반 2D PvE 생존 게임이다. 코드 전체를 읽었으며 브라우저 실행 검증은 하지 않았다.

- 기존 흐름: 시작 → 랜덤 상점에서 구매 → 대기석/격자 배치 → 자동 전투 → 승리 시 다음 라운드, 패배 시 재시작.
- 전투는 가까운 적을 찾아 이동하고 사거리 안에서 주기적으로 공격한다. 근접 공격, 원거리 투사체, 체력 표시와 사망 처리가 있다.
- 기존 규칙에는 레벨별 배치 수, 경험치 구매, 같은 유닛 3개 합성, 종족·직업 시너지, 라운드별 적 강화와 보스, 처치·승리 보상이 있다.
- 전투용 병사는 보유 목록에서 별도로 생성된다. 승리 후 보유 목록은 유지되며 다음 전투에서 체력이 다시 생성된다. 이 유지·회복 방식 역시 신규 게임의 확정 규칙이 아니다.

신규 게임에는 **배치 → 자동 전투** 흐름만 기본 참고로 삼는다. HTML의 “롤체 방식 그대로”라는 설명보다 위의 인간 군대·진형 중심 방향을 우선한다. **랜덤 상점, 3개 합성, 종족·직업 시너지는 우선 구현하지 않는다.** 그 외 HTML의 유닛 구성, 수치, 격자 크기, 경제와 생존 규칙도 자동으로 계승하지 않는다.

개발 순서와 현재 상태는 [PROGRESS.md](PROGRESS.md), 작업 방식은 [AGENTS.md](../AGENTS.md)를 따른다.
